# Waveshare time synchronization — 2026-08-26

Physical device: Waveshare ESP32-S3-Touch-AMOLED-2.06, USB serial
`28:84:85:B2:18:A4`. Measured firmware source commit: `1e51897` on PR #279.

## Measured

The final ESP-IDF v5.5.5 image was `0x163160` bytes in the 4 MiB application
partition, leaving `0x29cea0` bytes (65%). esptool wrote the bootloader,
partition table and application to `/dev/ttyACM1` and verified every hash.

The RTC had already been written as UTC by the preceding candidate. Immediately
after flashing the final candidate, before any timezone metadata existed, the
device framebuffer showed `03:06:45` and `time may be outdated`.

The host then sent one deliberate synchronization:

```text
$ python3 tools/watch_control.py --port /dev/ttyACM1 --timeout 20 sync-time --allow-large
time synchronized: UTC 1787713623, offset +300 min, trusted for 86400s
```

`TimeSyncOk` is emitted by this exact firmware only after the PCF85063 calendar
write, a valid readback within one second of the requested UTC, and an NVS
commit all succeed. The next physical-device framebuffer showed local
`08:07:08`; the stale warning was absent.

The device was then reset without erasing or rewriting flash:

```text
$ python -m esptool --chip esp32s3 -p /dev/ttyACM1 run
...
Hard resetting via RTS pin...
```

After boot, the framebuffer showed local `08:07:39` and
`time may be outdated`. This is the intended boundary: PCF85063 retained and
advanced UTC, NVS restored the `+300` minute presentation offset, and trust was
not reconstructed across the broken monotonic timeline.

A second synchronization needed no large-correction override:

```text
$ python3 tools/watch_control.py --port /dev/ttyACM1 --timeout 20 sync-time
time synchronized: UTC 1787713677, offset +300 min, trusted for 86400s
```

The following framebuffer showed local `08:08:03` with no stale warning. All
four captures came from the physical 410 × 502 device through its USB debug
channel and were opened at original resolution.

## Host-verified policy

Host tests cover raw RTC as provisional/stale, fresh and expired trusted
samples, source-quality precedence, explicit large corrections, negative and
expired timezone offsets, correction overflow, PCF85063 BCD validation and
encoding, fixed debug-protocol bytes, typed hardware failure, and the no-retry
host request. GCC strict-warning builds and the ESP-IDF firmware build passed.

## Evidence boundary

- **MEASURED:** the named device accepted host UTC, read the RTC back, persisted
  and restored the `+05:00` effective offset across reset, retained local
  display time, reinstated the stale state after reset, and returned to valid
  after synchronization.
- **HOST-VERIFIED:** source priority, freshness expiry, correction policy and
  timezone arithmetic execute in deterministic host tests.
- **UNKNOWN:** the host clock's error against an independent time standard,
  PCF85063 long-term drift, behavior across battery removal, DST/zone-rule
  distribution, and companion/network/GNSS/mesh synchronization providers.
- The framebuffer proves device state and rendered content, not optical panel
  luminance or independent metrological accuracy.
